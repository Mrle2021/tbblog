![个人内容生产系统：从灵感到长期知识资产](/images/personal-content-production-system/cover.webp)

这几天，我做了一件看上去有点“折腾工具”的事。

我把 Obsidian、Finder、ChatGPT、Desktop Commander、Hexo 和 Git 串了起来，搭了一套自己的半自动内容生产系统。

如果只看工具名单，这很容易变成另一篇“效率软件组合推荐”。但真正促使我做这件事的，并不是缺少工具。恰恰相反，我们现在已经拥有太多工具了。

真正的问题是：**每天看到的文章、视频、PDF、突然冒出来的想法，最后到底去了哪里？**

有些进了收藏夹，有些躺在 Downloads，有些留在聊天记录里，有些只存在脑子里几分钟。偶尔我会觉得其中某个东西“以后可以写”，但过几天再回头，常常只剩下一个链接，已经想不起当时为什么觉得它重要。

所以我这次想解决的，不是“怎样让 AI 更快写一篇文章”，而是另一个更基础的问题：

> 怎样让日常输入经过一层层加工，最后真正变成我自己的理解、判断和长期可以复用的内容资产？

## 我发现，收藏不是积累

以前我很容易把“保存下来”理解成“我拥有了它”。

看到一篇好文章，收藏；看到一个视频，保存；拿到一份 PDF，放进硬盘。时间久了，资料确实越来越多，但这些东西和我的关系并没有因此变得更深。

一个链接放在收藏夹里，和它从未出现过，有时没有太大区别。

这也是我现在越来越认同的一点：**知识管理的核心不是保存信息，而是加工信息。**

这次我放进系统里测试的一份材料，是 Dan Koe 关于如何把多重兴趣组织成内容与个人业务的一篇长文。他提出一个我觉得很有启发的概念：不要把每一篇内容看成孤立地扔向靶心的飞镖，而要把它们看成一张更大内容地图里的拼图。

这句话让我重新看待自己的博客。

我感兴趣的东西其实很多：AI、哲学、电影、音乐、阅读、知识管理、个人成长。以前很容易产生一种焦虑——是不是应该更“垂直”？是不是只能挑一个领域持续写？

但真正需要统一的，可能不是题材，而是这些题材最终服务于什么问题。

如果这些内容都在帮助我回答类似的问题：**在信息越来越多、AI越来越强的时代，一个普通人怎样保持自己的理解、判断和行动能力？**

那么哲学、AI、电影和知识管理，并不是彼此无关的几个栏目，而可能只是同一张地图上的不同区域。

## 所以，我把“存东西”和“想事情”分开了

![被整理成结构的笔记与资料](/images/personal-content-production-system/fig-01.webp)

这套系统里，我做的第一个决定，是不让所有东西都塞进 Obsidian。

PDF、视频、高清图片这些原始大文件，继续交给 Finder。它们更像证据原件和素材仓库。

Obsidian 则只保存另一类东西：**这份材料为什么值得留下，它说了什么，我怎么看，它和哪些已有想法有关，以及它未来可能变成什么。**

比如一份 PDF 进入系统以后，并不是简单地得到一个“PDF 已保存”的结果，而是进一步形成一张 Material Card：

- 来源是什么；
- 一句话总结是什么；
- 有哪些关键观点；
- 我自己的理解是什么；
- 哪些地方值得怀疑；
- 它可能发展成哪些选题。

我越来越觉得，“我的理解”这一栏才是整个系统真正的分界线。

在这之前，它只是外部信息。

写完这一栏之后，它才开始和我发生关系。

## AI 应该做很多事，但不应该替我做最后两个决定

![人与屏幕之间保留思考空间](/images/personal-content-production-system/fig-02.webp)

既然搭的是 AI 辅助系统，一个很自然的问题就是：为什么不干脆让 AI 自动选题、自动写完、自动发出去？

技术上，这并不是最困难的部分。

真正让我谨慎的是：**如果连“什么值得写”和“这到底是不是我的判断”都自动化了，这个博客最后还剩下什么？**

所以我最后给整个流程保留了两个明确的人工闸门。

第一个是选题。

系统可以读取本周新增素材，可以帮我整理历史候选，可以补充外部研究，可以一次生成十五个选题，再根据个人关联度、读者价值、独特性和可写性筛出 Top 5。

但最终选哪个，只能由我决定。

第二个是成稿。

AI 可以帮我补资料、搭结构、检查事实、寻找反方、发现逻辑跳跃，甚至生成一版相当完整的初稿。但文章最后能不能进入发布状态，必须由我确认。

所以整个状态链不是“AI 生成 → 发布”，而是：

素材 → Material → Topic → selected → researching → drafting → review → approved → published。

其中 selected 和 approved 都需要明确的人做决定。

对我来说，这不只是一个工作流设计，而是一条边界：**把机械劳动尽量交给机器，把价值判断尽量留给自己。**

## 为什么还要把 Obsidian 和 Hexo 分开

还有一个我以前没有认真想过的问题：文章到底“属于”哪里？

博客的文章最终需要进入 Hexo。Hexo 官方的写作机制很清楚，正式文章进入 source/_posts，再通过 Markdown 渲染成静态页面。

但我最后没有把 Hexo 当成主要写作空间。

我希望文章真正的源头始终留在 Obsidian。

也就是说，Obsidian 是 Single Source of Truth，Hexo 只是出版端。

这样做的好处是，写作和发布终于分开了。

在 Obsidian 中，我可以保留观点卡、来源、状态、尚未解决的问题，以及文章和其他笔记之间的关系。等一篇文章真正确认以后，再由脚本把它转换成 Hexo 所需要的 Front Matter、图片路径和文章文件。

这让我觉得，Hexo 更像一台印刷机。

它很重要，但它不应该成为思想发生的地方。

## Git 也从“备份工具”变成了发布边界

在搭这套系统的时候，我还遇到了一个非常具体的问题。

原来的博客发布脚本会执行 git add -A。

手动使用时，这很方便。但一旦进入自动化，它就变得危险：因为博客仓库里可能同时还有别的文档和脚本修改。如果自动发布一篇文章时执行 git add -A，完全可能把那些无关改动一起提交。

Git 官方文档对暂存区的解释其实非常准确：下一次 commit 包含什么，取决于你放进 staging area 的是什么。

所以我把这一层改成了白名单。

每次发布，只允许暂存：

- 当前这篇文章；
- 当前文章自己的图片目录。

其他工作区改动可以存在，但不能进入这次 commit。

这种设计看起来很小，却让我意识到：**自动化真正需要的不是“更少确认”，而是“更明确的边界”。**

如果一个流程只是在人不盯着的时候自动执行原来的命令，它不一定叫自动化，也可能只是把风险隐藏起来。

## 我真正想要的，是一个“精炼厂”

现在回头看，这套系统最核心的结构其实很简单。

所有东西先进入 Inbox。

然后不是全部保存，而是开始筛选。

有价值的外部材料变成 Material；值得发展的想法进入 Topic；确认后的 Topic 才进入 Writing；真正发布以后再进入 Published。

有些东西会在中间被丢掉。

这反而是我现在觉得最重要的一点。

因为一个好的知识系统，可能不应该像仓库一样什么都舍不得扔，而更像一个精炼厂：大量原始输入进去，真正留下来的只有少量能够支持长期思考的东西。

AI 在这里特别适合做筛选、摘要、关联、去重、事实核查和格式转换。

但如果最后没有形成自己的理解，它处理得再漂亮，也只是更整齐的收藏。

## 这套系统最大的风险，可能恰恰是系统本身

我当然知道，这里面还有一个很典型的陷阱。

知识管理、自动化和效率工具都很容易让人产生一种“我正在进步”的感觉。

搭文件夹、写脚本、调 Prompt、设计状态机，这些事情都有即时反馈，而且比真正坐下来写一篇文章轻松得多。

于是一个本来为了促进输出的系统，最后可能变成逃避输出的新方式。

所以我给自己定的目标其实很克制：每周一篇。

周五晚上选题，周六上午成稿。

不追求每天更新，不追求全自动，也暂时不追求把所有资料都整理进去。

如果这个系统最终不能让我更稳定地写出真正属于自己的文章，那它设计得再漂亮也没有意义。

## 我还没想清楚的问题

现在这套系统刚刚开始运行，我还没有想清楚一个更重要的问题：

**当 AI 深度参与研究、组织结构和初稿生成以后，一篇文章的“个人性”究竟来自哪里？**

也许不是来自每一个字都必须亲手敲出来。

它更可能来自：我选择关注什么，我留下什么材料，我拒绝什么观点，我在哪些地方感到犹豫，以及最后哪些判断愿意由自己负责。

如果是这样，那么未来真正稀缺的，也许不是写字的速度，而是选择和判断的能力。

这也是我想让 Trailblaze 继续验证的事情。
